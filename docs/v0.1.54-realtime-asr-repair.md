# 数字人 Agent v0.1.54 实时语音与 ASR 链路修复任务书

日期：2026-09-09
状态：已完成（2026-09-11 验收）

## 原始问题

数字人浏览器 Runtime 已能正常连接，但实时语音交互未形成可用闭环。需要定位并修复浏览器麦克风采集、认证网关 WebSocket 转发、Agent 音频帧处理和本地 ASR 转写之间的断点，重点验证语音转文字结果。

## 目标

1. 将当前项目的已验证代码推送到新的 GitHub 私有仓库，排除本地凭证、运行数据、模型缓存和临时诊断材料。
2. 以实际运行链路为依据定位实时语音失效原因，修复最小必要代码。
3. 确保浏览器音频采集、PCM16 帧传输、ASR final transcript 和 Agent 自动回复可以端到端工作。
4. 保留可诊断日志，但不记录原始语音、登录令牌或供应商凭证。

## 验收标准

- GitHub 远程仓库为私有仓库，默认分支和当前工作分支均已推送，工作树不包含凭证或运行数据。
- 本机 ASR 服务健康，使用已知 PCM16 样本和空音频分别返回可验证的转写或空结果。
- 浏览器进入实时对话后可取得麦克风权限，发送 `audio_start`、PCM16 二进制帧和 `audio_end`。
- Agent 对最终转写发送 `transcript.status=final`，随后创建并完成对应 Agent run。
- 相关前端、认证网关、Agent、ASR 自动化测试和 Docker 运行验证通过。
- 本地 Docker 使用包含修复的最新镜像，健康检查通过。

### 二、实时链路修复（三处阻断）

1. **宿主代理绕过**：Agent 到 `asr-service` 的内部请求不再走宿主代理。`HttpAsrIngress` 按 endpoint 主机名判定 `trust_env`（仅主机名等于 `asr-service` 时关闭代理继承），并在 Compose 中补齐 `NO_PROXY` 服务名列表。
2. **麦克风早期禁用**：魔珐会话声明语音输入能力，前端不再在 WebSocket 就绪前禁用麦克风。
3. **录音启动与媒体流复用**：
   - 首页首次录音在点击事件内同步启动，保证浏览器用户手势上下文有效。
   - 连续对话复用已授权媒体流。
   - 处理授权期间取消、并发启动、以及音轨失效后的重采集。
4. **ASR 错误呈现**：ASR 失败以明确错误呈现，不再被降级当作空的最终转写。

### 五、注意事项

- `/transcribe` 鉴权使用 `Authorization: Bearer <ASR_INTERNAL_TOKEN>`，与 Agent 内部 `X-Internal-Token` 是两套机制，勿混淆。
- `auth-service` 健康端点为 `/api/health`（非 `/health`）；`/health` 返回 500 属正常现象。
- `NO_PROXY` 中登记的是短服务名；使用全名（`ican-digital-human-*-1`）访问会被宿主代理拦截并返回 502。
