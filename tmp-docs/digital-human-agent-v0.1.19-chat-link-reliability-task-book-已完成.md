# 数字人 Agent v0.1.19 链路可靠性修复任务书

## 1. 原始问题

首页文本对话依赖实时 WebSocket 连接状态。星云浏览器运行时或实时通道建立较慢时，用户无法发送文本，只能反复点击或重复提交，前一轮请求随后被中断，界面连续显示“本次响应已打断”，数字人也无法稳定播报 Agent 回复。

## 2. 修复目标

1. 文本对话使用独立 SSE 链路，数字人实时通道未就绪时仍可发送。
2. 语音按钮继续受实时通道和音频能力约束，避免把不支持的能力伪装成可用。
3. 会话创建期间禁止重复创建，避免产生多个并发会话和对应的重复请求。
4. 最新指令可以中断旧响应，但旧响应不能覆盖新响应；正常完成时必须清理运行状态。
5. 连接或上游异常时保留可读的失败状态，支持用户重新发送，不再停留在永久 pending。

## 3. 实施范围

- `apps/web/src/features/chat/components/HomeConversationBar.tsx`
- `apps/web/src/pages/HomePage.tsx`
- 前端链路契约测试
- 版本号更新至 `0.1.19`

## 4. 验收标准

- 已创建会话但 WebSocket 状态为 connecting/disconnected 时，文本输入框和发送按钮可用。
- 未创建会话时首次发送只创建一个会话；创建进行中再次提交不会发起第二次创建。
- 新指令到达后，旧 SSE 请求被取消并发出带运行 ID 的中断请求；旧事件不会写入新消息。
- SSE 收到 `done`、`interrupted`、错误或连接结束后，发送状态最终恢复为非发送中。
- Web 端构建、布局/实时链路测试通过，后端现有测试不回归。
- 任务完成后文档重命名为带 `-已完成` 后缀的文件。
