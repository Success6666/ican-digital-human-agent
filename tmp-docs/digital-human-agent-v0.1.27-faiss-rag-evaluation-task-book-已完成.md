# 数字人 Agent v0.1.27 FAISS、RAG 交互与评测数据集任务书

## 原始问题

1. RAG 当前使用 SQLite 保存向量并在 Python 中逐条计算相似度，知识规模增长后检索延迟线性上升。
2. RAG 页签未完全形成互斥的页内视图，用户切换后仍可能看到追加在页面下方的重复功能块。
3. 评测中心虽已有评测代码骨架，但需要补齐可执行、自建、贴合数字人实时链路的数据集，并确认前端展示来自真实后端数据。

## 修复方案

### FAISS 检索

- 使用 FAISS 维护每个知识库命名空间的向量索引。
- SQLite 继续承担文档、切片、元数据和索引映射的持久化，FAISS 承担向量近邻检索。
- 索引文件持久化到运行数据卷，支持容器重启复用；写入、删除后保持 SQLite 与 FAISS 一致。
- 增加并发锁、空索引处理、损坏索引重建和维度校验。

### RAG 页内视图

- 知识库管理、文档管理、检索测试三个页签互斥渲染。
- 删除页签下方重复展示的功能区。
- 每个视图继续调用真实后端接口，保留上传、创建、启停、检索等交互。

### 评测数据集

- 建立覆盖实时改口/中断、RAG 有据性、MCP 路由、工具准确率、数字人播报与表情动作、延迟、成本、一致性和提示词注入的自建数据集。
- 提供数据集列表、详情和按数据集运行评测的真实接口。
- 前端显示实际样本数、维度、运行状态和结果，不使用静态指标。

## 验收标准

- [x] FAISS 替代 Python 全量余弦扫描并完成持久化。
- [x] RAG 文档上传、入库、删除、检索测试通过。
- [x] RAG 三个页签只渲染当前视图，不向页面下方追加其他视图。
- [x] 至少一套项目自建评测数据集可通过 API 查询并执行。
- [x] 评测数据覆盖 Agent、RAG、MCP、实时数字人、成本、延迟与安全核心维度。
- [x] 前端评测中心只展示真实 API 数据。
- [x] 后端、前端相关测试和构建通过。
- [x] Docker 服务重建后健康。
- [x] 版本提升到 `0.1.27` 并提交。
