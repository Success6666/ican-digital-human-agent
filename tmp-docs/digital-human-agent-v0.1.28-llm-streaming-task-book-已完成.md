# 数字人 Agent v0.1.28 模型链路与流式响应任务书

## 原始问题

1. 已配置的 OpenAI 兼容模型频繁进入不可用回退，缺少可区分的请求错误与抗瞬时网络故障能力。
2. Agent 的 SSE 表面上分片输出，实际需要等待模型完整响应后再切片，首个真实内容延迟较高。
3. 首页连接成功后，断开按钮移动到场景右上角，与连接操作位置不一致。

## 修复方案

- 规范化模型端点，兼容基础地址和完整 `chat/completions` 地址。
- 使用异步流式 HTTP 请求，分离连接、读取、写入和连接池超时。
- 对建连、DNS 和上游临时故障实施有界指数退避重试，保留可观测错误摘要。
- 使用 LangGraph 自定义流将模型增量直接推送至 SSE，同时在完成后解析数字人表情与动作结构。
- 将连接和断开操作合并为数字人场景底部同一位置的双态按钮。

## 验收标准

验证记录：真实 OpenAI 兼容端点已返回 SSE 增量，当前运行环境实测首个上游 chunk 约 34.2 秒、完整响应约 35.8 秒；此前暖机请求曾达到约 2.7 秒。该延迟来自上游响应抖动，不是鉴权失败；空 choices 用量尾帧可正常结束。Mock 全链路确认浏览器收到真实 `delta` 事件；后端全量测试 169 passed, 1 skipped；前端 `npm run build` 通过；Docker 服务健康。
