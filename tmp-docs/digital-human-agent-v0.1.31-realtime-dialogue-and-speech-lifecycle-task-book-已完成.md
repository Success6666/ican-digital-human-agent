# Digital Human Agent v0.1.31 实时语音与播报生命周期修复任务书

## 状态

已完成（2026-09-01）

## 原始问题

1. 星云 SDK 收到新一轮 `speak_start` 时，上一轮仍未进入确定终态，触发兜底结束并中断数字人画面。
2. 首页语音按钮采用手动开始、手动结束后才提交整段音频的交互，实际行为是语音转文字，不是持续实时对话。
3. 浏览器语音识别降级路径使用单次识别，结束后不会自动继续监听。
4. 实时会话缺少自动分段、连续轮次恢复、用户开口打断数字人和播放结束后的监听恢复闭环。

## 实施方案

1. 检查 trace、WebSocket 事件与星云 SDK 回调，明确 run、utterance、播放和播报的终态边界。
2. 为星云播报增加显式代际、结束确认、串行队列和超时恢复，旧轮次不得覆盖新轮次状态。
3. 将首页语音入口改为持续会话开关：开启后保持麦克风监听，由浏览器连续识别自动形成最终片段并提交 Agent；原生 PCM 通道保留为后续接入真实 ASR 的扩展点。
4. 用户重新开口时沿现有消息切换与数字人中断链路立即终止旧轮次，避免旧 run 继续播报。
5. 浏览器语音识别启用连续模式、自动重启和最终片段自动提交，关闭实时模式后释放识别实例和重启定时器。
6. 增加状态机、过期事件、动作白名单和自动恢复测试，并执行生产构建、Docker 重建和真实 API 链路验证。

## 验收标准

1. 星云播报按 `onSpeakStateChange(speak_end)` 串行推进；重叠警告只进入可恢复状态，不再覆盖数字人画面。
2. trace 中已验证 run 以 `status=ok`、`event_count=12`、`cancelled=false` 收敛，前端门禁会丢弃终态后的晚到事件。
3. 点击一次语音按钮进入持续实时对话，用户停顿后自动提交，不需要再次点击结束。
4. 数字人播报结束后自动恢复监听；用户中途开口可在可感知时间内打断上一轮。
5. 连续完成至少三轮语音对话，utterance/revision/run 不串线、不丢终态。
6. 前端测试与生产构建通过；后端相关测试 28 项通过；Docker 五个服务健康；真实管理员登录、星云会话创建、同步 Agent 回复和 SSE `done` 终态验证通过。

保留修改前关键文件副本、完整差异、验证记录和可执行回滚脚本；回滚后恢复 v0.1.30 的单次录音与原星云播报队列行为。验证记录见 `tmp-docs/v0.1.31-artifacts/VERIFICATION.txt`。
