# Digital Human Agent v0.1.35 性能、体验与评测数据任务书

## 状态

已完成（2026-09-01）

## 原始问题

1. 评测运行主要保存在内存，进程重启后无法追溯每一轮原始输入、原始输出和评分上下文。
2. 内置评测样本覆盖面不足，缺少缓存命中、租户隔离、个性化、ASR/TTS、RabbitMQ、并发、降级恢复和前端体验等分类。
3. 前端评测页虽然调用真实接口，但缺少分类筛选、运行详情、原始数据查看和明确的加载/错误/空状态。
4. 前端多个页面存在重复刷新、粗粒度等待和信息密度不均的问题，需要在不改变业务契约的前提下降低无效请求并改善操作反馈。

## 目标

1. 保持现有真实后端接口链路，消除评测页的静态兜底误导，补齐运行详情和原始数据入口。
2. 扩充评测集到不少于 60 个样本，按安全、质量、RAG、工具治理、实时音频、可靠性、性能、租户隔离、个性化、缓存、用户体验、可观测性和成本分类。
3. 每轮评测将完整原始请求、原始输出、评分结果、trace、时间和执行元数据追加写入持久化归档；内存仅保留有界索引用于快速聚合。
4. 优化评测运行查询、页面刷新、筛选和详情查看的响应路径，避免重复请求和无界渲染。

## 验收标准

1. 重启 Agent 后，历史评测运行仍可按账号读取；不同账号只能读取自己的运行和原始数据。
2. 原始归档为追加写入，包含每轮的完整 input/output、请求参数、评分、trace、状态、时间和错误元数据。
3. 默认数据集样本数不少于 60，分类数不少于 12，且每个新增分类至少有 2 个样本。
4. 前端评测页所有数据来自真实 `/api/evaluation/*` 接口，支持分类筛选、运行数据集、查看运行详情和原始输入输出；加载、失败、空结果状态可区分。
5. Agent 全量测试、Auth 测试、Web 测试和 Compose 健康检查通过；评测归档重启 smoke 通过。
6. 任务书完成后重命名为 `...-已完成.md`，生成基线、修改、差异、验证和可执行回滚 artifacts，并提交版本变更。

## 回滚方案

恢复 v0.1.34 入口和页面，保留已生成的原始评测归档文件；回滚脚本只操作验证副本，不覆盖工作树源码。

## 验收结果

1. Agent 使用追加式 JSONL 原始归档恢复最近有界索引；重启 smoke 已验证请求数据恢复，账号隔离返回 404。
2. 默认数据集为 64 个样本、19 个分类，新增覆盖安全、质量、RAG、工具治理、实时音频、可靠性、性能、租户隔离、个性化、用户体验、可观测性、成本和边界场景。
3. 评测页通过认证网关访问真实 `/api/evaluation/*` 接口，支持分类筛选、运行列表、原始数据查看，并保留加载失败时已有数据。
4. Agent 测试 `189 passed, 2 skipped`；Web 构建及 11 项 Node 测试通过；Auth Maven 测试退出码为 0；Compose 六个服务均为 healthy。
5. 验证与回滚材料位于 `tmp-docs/v0.1.35-artifacts/`，回滚副本已恢复且工作树修改副本保持变更。
