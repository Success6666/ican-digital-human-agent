# Digital Human Agent v0.1.36 用户体验锐评与评测图表任务书

## 状态

已完成（2026-09-01）

## 锐评基线

1. 评测中心当前以大量小指标卡片承载信息，用户需要在多个孤立数字之间自行拼趋势，无法快速判断系统是在变好还是变差。
2. 评测运行虽然能查看原始归档，但默认展示偏机器字段，用户仍需理解 token、枚举状态和内部时间字段，认知负担过高。
3. 数据集、运行记录、指标摘要和原始数据的层级关系不够清楚，页面缺少“先看结论、再看趋势、最后钻取证据”的阅读顺序。
4. 当前视觉层级偏工具堆叠，空白、标题、操作和表格之间缺少明确节奏；小屏幕下信息密度下降后，重点更难被发现。

## 目标

1. 将评测中心重构为趋势优先的工作台：质量、延迟、资源成本等相关指标合并为少量可读图表。
2. 图表默认展示最近十次评测结果，点击任意数据点或“查看全量”进入全量明细，保留原始归档钻取。
3. 所有面向用户的值使用中文标签、单位和状态文案；内部字段仅在原始数据查看区域按需展示。
4. 调整前端布局、间距、层级、空状态、错误状态和响应式行为，减少无效卡片和重复操作。

## 验收标准

1. 评测中心不再使用成组小指标卡片展示核心指标；核心信息由质量趋势、延迟趋势、资源趋势等图表表达。
2. 每张趋势图默认显示最近十次结果，横轴可读、悬停/点击可定位具体运行，支持查看全量运行数据。
3. 图表与明细数据均来自真实 `/api/evaluation/*` 接口，不新增静态评测数据；无数据、加载中、失败均有明确人话提示。
4. 桌面端与窄屏布局通过构建和现有前端测试，文本、图例、按钮不溢出，不依赖颜色作为唯一语义。
5. Agent、Auth、Web 和 Compose 回归验证通过；版本升级、任务书归档、基线/修改/差异/回滚材料齐全。

## 回滚方案

保留现有评测接口契约，回滚时恢复 v0.1.35 的评测页面与样式；回滚脚本只操作验证副本，不覆盖工作树源码。

## 验收结果

1. 评测中心已移除核心小指标卡片，改为质量走势、响应时延、Token 用量和运行成本四张趋势图；每张图默认显示最近十次运行。
2. 图表数据点可直接打开单轮详情，详情先展示中文状态、百分比、耗时、Token、成本、用户输入和数字人回答；机器字段仅在“查看原始字段”区域展开。
3. “查看全量数据”会展开当前已保留的全部运行，数据仍来自真实 `/api/evaluation/*` 接口，无静态评测 fixture。
4. 前端生产构建通过；聊天 `3` 项、实时 `5` 项、布局 `4` 项、数字人 `3` 项测试通过；Agent `190 passed, 2 skipped, 1 warning`；Auth Maven 退出码 `0`。
5. Compose 重建后 Agent、Auth、MCP、Web、Redis、RabbitMQ 全部 healthy，网关健康接口返回 HTTP 200。
6. 基线、修改、差异、验证和可执行回滚材料已生成于 `tmp-docs/v0.1.36-artifacts/`，回滚副本比对通过。
