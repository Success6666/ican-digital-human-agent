# 数字人会话历史与流式回归修复任务书

日期：2026-09-02  
版本：v0.1.42  
状态：已完成

## 原始问题

1. 数字人流式回复期间打开历史记录，页面出现明显卡顿或卡死。
2. 已移除的预设理解提示仍可能由旧缓存、旧构建或 filler 事件路径显示。
3. 历史消息只存在于当前页面内存，刷新或重新进入后丢失，用户不能选择旧会话继续。
4. 公网 `6666` 端口被 Chromium/Edge 直接以 `ERR_UNSAFE_PORT` 拦截；魔珐 SDK 还要求安全上下文，普通 HTTP 即使接口可达也不能完成数字人初始化。
5. 公网 `16666` 来源未进入认证服务 CORS 白名单，创建数字人会话持续返回 403；快速重复点击还会产生并发创建请求，造成加载完成后延迟显示。
6. 魔珐 SDK 在 `init()` 尚未完成时提前上报 ready，页面过早解锁输入，随后模型与首帧长任务造成短时假死。
7. 文本提交会在数字人空闲时无条件调用魔珐中断接口，阻塞 SDK 主线程并表现为提交后页面卡死。
8. 聊天消息与发送状态变化会连带重渲染供应商 canvas 宿主组件，React 与 SDK 同时触碰画布树时会放大主线程卡顿。
9. 流式首句进入等待队列后，worker 在 `finally` 中无条件重启，形成不可推进的 Promise 微任务自旋并饿死浏览器主线程。

## 实施方案

1. 历史抽屉使用打开瞬间的不可变快照，并通过组件记忆化隔离实时消息增量。
2. 前端不再向消息气泡写入 filler 文本，清理旧响应缓存并重建运行镜像。
3. 按认证账号持久化会话目录和消息，支持新建、选择、删除与继续对话。
4. 增加可信 HTTPS 的 `16666` 公网入口，保留 `6666` 作为兼容入口，并配置短周期 IP 证书自动续期。
5. 为公网来源补齐 HTTP 与 WebSocket CORS，并对数字人会话创建增加单飞保护。
6. 数字人就绪改为等待 SDK 初始化、首帧信号和稳定绘制帧后再解锁交互。
7. 仅在数字人正在播报时发送中断信号，空闲文本提交不触发供应商 SDK 中断。
8. 记忆化数字人 Runtime 宿主，仅在会话、可见性或实际播报内容变化时重渲染。
9. 仅在有新句段、缓冲文本或最终 flush 时重启播报 worker，单段等待状态不再自旋。
