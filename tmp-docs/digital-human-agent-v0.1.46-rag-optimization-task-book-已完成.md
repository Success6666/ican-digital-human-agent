# 数字人 Agent v0.1.46 RAG 全链路优化任务书

状态：已完成  
版本：v0.1.46  
日期：2026-09-02

## 原始问题

当前 RAG 使用字符级切片、单层 chunk、同步 Embedding、SQLite 全量读取和 FAISS `IndexFlatIP`。文档结构、父子上下文、向量维度、索引参数、缓存和召回评测尚未形成可调优闭环，导致知识召回延迟和准确率都不稳定。

## 目标

1. 在不破坏租户/账号命名空间隔离的前提下优化文档解析、结构化切片、父子分块、向量生成、索引构建和召回排序。
2. 通过查询向量缓存、检索结果缓存、索引驻内存和批量 Embedding 降低热路径延迟；所有缓存设置 TTL 和容量上限，避免内存无限增长。
3. 建立覆盖结构化文档、长文本、问答、数字人业务知识和租户隔离的 RAG 评测数据，并保留每轮原始结果。
4. 用 p50/p95、Recall@K、MRR、证据覆盖率和端到端首 token 延迟验证优化效果；“毫秒级”按缓存命中、索引检索和本地热路径分别验收，不把 LLM 生成时间冒充检索延迟。

## 实施边界

- 优先复用现有 `RagService`、`CharacterChunker`、`FaissVectorStore` 和 Embedding Port，保持 API 兼容。
- 父块用于上下文恢复，子块用于向量召回；结果按父文档/相邻块去重和合并。
- 默认使用本机 SentenceTransformers `BAAI/bge-small-zh-v1.5`；Hash Embedding 仅保留为显式离线测试适配器，不参与生产默认链路。
- 任何新缓存必须具备 TTL、最大条目数、租户/集合键隔离和失效策略。
