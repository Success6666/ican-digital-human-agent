# Digital Human Agent v0.1.5 后台配置任务书

**状态：已完成**  
**创建日期：2026-08-30**  
**完成日期：2026-08-30**

## 目标

将后台配置从只读状态页改为受控、可持久化的运行配置入口。页面只展示可扫描的摘要卡片；具体配置在小型弹窗中完成。

## 范围

1. 为默认数字人 Provider、会话有效期和清理间隔建立读取、校验、保存、运行时应用的完整链路。
2. 配置数据仅保存非敏感运行参数，Provider 密钥和供应商凭证继续由部署环境管理。
3. 将配置入口收敛为摘要卡片和弹窗表单，移除页面内展开的配置目录、表格和策略清单。
4. 增加管理员修改权限、参数边界校验、原子文件写入和回归测试。

## 实施步骤

1. 在 Agent 服务中增加持久化运行配置仓储及更新用例，同步 Provider Registry、会话存储、清理任务。
2. 增加内部 PATCH 接口及认证网关代理，仅允许管理员提交变更。
3. 为 Web API 增加 PATCH 封装和配置保存状态管理。
4. 新建后台配置摘要与弹窗组件，统一输入框、选择器、状态和错误反馈样式。
5. 删除已不再使用的展开式配置组件和样式，完成版本升级、构建和回归验证。

## 验收标准

1. 管理员在弹窗中保存 Provider、会话有效期和清理间隔后，刷新页面仍能读取相同配置。
2. 非管理员调用写配置接口得到 403，敏感环境变量和密钥不会出现在请求、响应或页面中。
3. 被选 Provider 必须存在且可用；数值必须落在服务端定义的安全范围内，非法请求得到 422。
4. 新建会话使用更新后的默认 Provider；新会话 TTL、存储续租和后台清理任务使用更新后的数值。
5. 配置页默认不展开字段、模型表格或策略表；点击摘要卡片后仅显示紧凑弹窗。
6. 弹窗内的选择器、数字输入、按钮和错误状态与控制台设计令牌一致，并通过桌面和移动端视觉检查。
7. Agent 服务测试、认证网关测试和 Web 生产构建通过；功能代码提交为独立的 v0.1.5 提交。

## 验收结果

1. 运行配置可通过管理员接口更新，原子写入持久化文件，并在服务重启后恢复。
2. 默认 Provider、会话有效期和清理间隔可即时应用；非法配置返回 422，非管理员返回 403。
3. Provider 凭据仅存在于本地部署环境，配置响应及前端页面不包含密钥字段。
4. 后台配置已改为摘要卡片与独立弹窗，桌面端和移动端均无横向溢出。
5. Agent、认证网关、MCP 测试及 Web 生产构建、Docker Compose 配置检查均通过。
