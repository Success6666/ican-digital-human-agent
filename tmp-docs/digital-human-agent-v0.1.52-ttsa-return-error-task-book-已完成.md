# v0.1.52 TTSA 返回异常修复任务书

## 原始问题

数字人资源已经渲染，但页面显示“星云运行时：TTSA 返回异常”，人物画面被半透明错误层覆盖，用户无法判断是渲染失败、网络断开还是星云服务暂时无房间。

## 链路复现

1. 浏览器通过 `/api/sessions` 获取 Mofa SDK 参数。
2. 按 SDK 2.1.3 的签名算法直接调用 `POST https://nebula-agent.xingyun3d.com/user/v1/ttsa/session`。
3. 2026-09-03 实测返回 HTTP 200、业务 `error_code=1`、`星云暂无空闲房间, 请稍后再试`。
4. SDK 对 WebSocket `error_message` 统一转换为 `code=40006`、`TTSA 返回异常`，前端原逻辑把所有带 message 的回调都归为致命错误。

## 修复方案

1. 增加 `warning` 状态，将 TTSA 房间不足和 `40006` 业务告警与网络断开、初始化失败分开。
2. 保留人物已渲染画面，显示真实错误原因与错误码，并提供重试入口。
3. 对 `TTSA 返回异常` 做兼容兜底，但不吞掉供应商原始错误。
4. 增加回归测试、构建和容器冒烟验证。

## 验收标准

- [x] TTSA 业务错误不再被标记为初始化致命错误。
- [x] 错误码 1 显示“暂无空闲房间”等真实原因。
- [x] 错误码 40006 显示可识别的 TTSA 暂不可用提示。
- [x] 已渲染人物仍保持可见，页面提供重试按钮。
- [x] Web 测试和生产构建通过，容器健康。
- [x] 原始文件、修改文件、差异、回滚脚本和验证记录齐全。

## 实际验收结果（2026-09-03）

- SDK 2.1.3 签名会话请求实测返回 HTTP 200、`error_code=1`、`星云暂无空闲房间, 请稍后再试`。
- Web 魔珐测试：`8 passed`；生产构建成功。
- 回滚脚本在副本上执行成功，未改动工作文件。
- 版本：`v0.1.52`。
