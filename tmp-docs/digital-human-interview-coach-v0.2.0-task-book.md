# 面试官数字人：Agent 与 RAG 实时智能面试训练系统

## 1. 原始目标

在现有数字人 Agent 工程上收敛到“数字人求职面试教练”场景，并形成一条可演示、可扩展的训练闭环：

`JD 链接/文本 + 简历 + 公司背景 + 面经/评分标准 -> 岗位画像 -> 多轮面试 -> 动态追问 -> 结构化评估`

新增 Agent 的 WebFetch 能力与 Playwright 无头浏览器能力，支持用户提交 Boss 直聘、实习僧等求职平台的 JD 链接，自动提取岗位、要求、公司信息；随后检索公司业务信息，结合岗位和简历生成针对性面试。抓取结果自动进入 RAG，后续同源抓取只做增量更新。

## 2. 本阶段范围

### 2.1 必须交付

1. 独立开发分支 `feature/interview-coach-agent-rag`，不合并 `main`。
2. 面试训练领域模型与会话状态：
   - 结构化面试、岗位专项面试、压力面试；
   - 一面、二面、三面、HR 面阶段；
   - 当前问题、回答、追问、跳过、提示、改口和中断恢复。
3. JD 输入能力：
   - 接受 JD URL 或直接文本；
   - URL 校验、SSRF 防护、超时、响应大小、重定向限制；
   - Playwright 无头浏览器抓取动态页面；
   - 保留原始来源、抓取时间、内容哈希和可追踪元数据。
4. 简历输入能力：
   - 接受 PDF/DOCX/TXT；
   - 复用现有 Docling/RAG 入库路径；
   - 限制文件大小与 MIME/扩展名；
   - 简历内容与用户会话隔离。
5. 增量 RAG 入库：
   - 以规范化来源 URL、文档类型和内容哈希识别重复内容；
   - 内容未变化时跳过解析和向量写入；
   - 内容变化时保留版本关系并更新检索内容；
   - JD、公司背景、面经、简历使用明确 metadata。
6. Agent 面试策略：
   - 根据岗位、简历、公司业务和面经生成阶段策略；
   - 根据回答质量决定追问或切换；
   - 输出可供数字人播报的短问题和动作/情绪提示。
7. API 与测试：
   - 创建面试训练会话；
   - 上传简历；
   - 抓取并导入 JD；
   - 导入公司背景；
   - 推进面试回合；
   - 生成结构化评估；
   - 覆盖安全边界、增量行为和关键状态转移。

### 2.2 本阶段不做

- 不把前端直接暴露为可绕过认证的服务；
- 不实现真实招聘平台账号登录、验证码绕过或批量采集；
- 不把公司搜索结果当作无来源事实；
- 不改造与面试闭环无关的数字人 Provider、设置页和既有实时协议；
- 不在没有保留策略的情况下删除历史 RAG 或 LangGraph checkpoint。

## 3. 技术方案

### 3.1 模块

- `app/interview/`: 面试领域模型、阶段状态机、策略编排、评估模型。
- `app/webfetch/`: URL 规范化、SSRF 检查、Playwright 抓取、文本抽取和来源元数据。
- `app/rag/`: 在现有 Store 上增加来源指纹、版本和增量导入服务。
- `app/api/`: FastAPI 路由、请求体/文件限制和认证边界。
- `tests/`: 单元、API 和端到端链路测试。

### 3.2 抓取链路

1. 校验 URL 只允许 `http/https`，解析 DNS/IP 并拒绝回环、私网、链路本地和保留地址。
2. 使用 Playwright Chromium headless 访问，限制导航次数、超时、页面大小和资源类型。
3. 从页面正文与 JSON-LD 提取岗位名称、公司、地点、职责、任职要求和福利。
4. 对公司信息生成独立搜索任务；每条结果保留 URL、标题、摘要、时间和来源类型。
5. 使用 `source_key + content_hash` 判断 unchanged/incremental/first_seen。

### 3.3 面试状态机

阶段顺序默认：

`first_round -> second_round -> third_round -> hr_round -> completed`

每轮保存：

- 问题类型、问题文本、回答文本、回答版本；
- 是否追问、追问原因、面试官动作；
- 岗位能力维度评分和证据；
- 面经/评分标准的 RAG 引用；
- 中断、改口、提示和恢复事件。

## 4. 安全与资源约束

- 所有抓取请求使用服务端超时、最大响应体和并发上限。
- URL 经过 DNS/IP 校验，禁止访问内部网络与本机管理端口。
- 不执行页面脚本中的下载、文件访问、剪贴板或任意外部协议。
- 文件名只作为展示字段，存储使用服务端生成的 ID。
- 原始网页和简历内容按用户/租户隔离，不进入日志。
- Playwright Browser/Context/Page 在成功、失败和取消路径均关闭。
- 通过缓存和内容指纹降低重复抓取；通过任务状态暴露抓取进度和失败原因。

## 5. 验收标准

### A. 分支与工程

- [ ] 当前工作分支为 `feature/interview-coach-agent-rag`。
- [ ] 不产生对 `main` 的合并或提交。
- [ ] 新增代码遵循现有 FastAPI、Pydantic、RAG 和测试结构。

### B. WebFetch

- [ ] 合法 JD URL 可以抓取并返回岗位与公司结构化信息。
- [ ] 动态渲染页面可通过 Playwright 获取正文。
- [ ] 私网、回环、链路本地、非 HTTP(S) URL 被拒绝。
- [ ] 超时、超大响应和浏览器异常可观测并释放资源。

### C. RAG 增量

- [ ] 首次抓取入库。
- [ ] 相同来源且内容未变化时返回 `unchanged`，不重复解析/写入。
- [ ] 内容变化时返回 `incremental`，生成新版本并保留来源关系。
- [ ] 简历、JD、公司资料、面经 metadata 可区分并参与检索过滤。

### D. 面试闭环

- [ ] 能创建包含岗位、简历和面试模式的训练会话。
- [ ] Agent 能按一面到 HR 面推进，并能追问/跳过/提示/改口。
- [ ] 每个问题有可追溯的评分维度和 RAG 依据。
- [ ] 结束后生成表达、完整性、岗位匹配、STAR、技术深度和改进建议。

### E. 验证

- [ ] 运行现有 Agent 服务测试。
- [ ] 运行新增 WebFetch、增量 RAG、面试状态机和 API 测试。
- [ ] 记录基线、修改后和回滚验证命令及结果。
